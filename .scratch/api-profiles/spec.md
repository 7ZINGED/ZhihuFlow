# API 配置档案与连通性测试

## Problem Statement

用户只有一个扁平的 AI 设置：切换 DeepSeek / OpenAI / Kimi / Ollama 时，预设按钮只改接口地址与模型名，Key、提示词、批次上限仍共用一份。要同时维护「工作用 DeepSeek」和「本地 Ollama」两套环境，只能反复手填并冒着覆盖另一套 Key 的风险。

用户也没有办法在正式跑一批文章前确认当前接口、模型和 Key 是否真的可用；只能等队列失败后才从错误里猜原因。

更关键的是：ADR-0002 规定 Key 只存 `chrome.storage.local`、不写导出文件，但现有备份实现把整个设置（含 apiKey）写进 JSON。用户明确要求任何 API Key 都不得进入 git 提交。多份档案会让 Key 的暴露面扩大，必须在引入档案的同时把 Key 隔离做实。

## Solution

把 AI 设置重组为**命名的 API 配置档案**：每份档案携带接口地址、模型、Key、提示词与批次上限；一份 `active_profile_id` 指向对新任务生效的档案。旧的单份设置迁移成默认档案，数据不丢。

队列任务在入队时**快照**当时的档案；运行中切换档案只影响新任务，在途任务不会被换 Key 或换模型。

在设置面板提供**连通性测试**：用目标档案发一次极小真实请求（`max_tokens=1`），返回成功耗时与模型名，或分类后的错误原因；它走与正式 AI 调用相同的公共缝，组件不直接发请求。

同时落实 Key 隔离：导出备份时把档案里的 Key 置空，导入后要求用户重新填写；测试与文档只用假 Key；提交前扫描 staged diff，命中疑似 Key 即阻断。

## User Stories

1. 作为用户，我想保存多份命名的 API 配置档案，以便在家用本地模型、在公司用云端模型，互不覆盖。
2. 作为用户，我想一键切换激活档案，以便新任务立刻使用目标平台的接口、模型、Key 和提示词。
3. 作为用户，我想给档案重命名，以便用「工作 DeepSeek」「本地 Ollama」这类名字区分用途。
4. 作为用户，我想删除不再使用的档案，以便设置列表保持简洁。
5. 作为用户，我想保留至少一份档案且不能删除激活档案的默认项，以便系统始终有可用配置。
6. 作为用户，我想首次升级时旧设置自动变成一份默认档案，以便不丢失已填的接口、Key 和提示词。
7. 作为用户，我想在队列运行中切换档案而不影响在途任务，以便已付费的任务可复现。
8. 作为用户，我想让新入队的任务使用切换后的档案，以便后续批次用上新平台。
9. 作为用户，我想对指定档案做连通性测试，以便知道该档案的接口、模型与 Key 是否可用。
10. 作为用户，我想在测试成功时看到耗时与返回模型名，以便确认连到的是预期服务。
11. 作为用户，我想在测试失败时看到分类错误（配置缺失 / 鉴权失败 / 网络不通 / 响应异常），以便快速定位问题。
12. 作为用户，我想连通性测试只发极小请求，以便不消耗可观额度。
13. 作为用户，我想测试按钮使用当前正在编辑的档案值，而不是已保存的旧值，以便改完 Key 能立刻验证。
14. 作为用户，我想导出备份时档案里的 Key 被置空，以便备份文件可以安全分享。
15. 作为用户，我想导入备份后看到「需重新填写 Key」的提示，以便知道为什么测试会失败。
16. 作为用户，我想导入旧版本备份（扁平 settings）时仍能迁移成档案，以便历史备份可用。
17. 作为用户，我想接口预设按钮只填接口地址与模型名，不碰 Key、提示词与上限，以便预设不会意外覆盖同档案的其他设置。
18. 作为开发者，我想档案逻辑集中在一个深模块，接口小、行为多，以便测试与维护都只跨一个缝。
19. 作为开发者，我想连通性测试函数从 AI 模块导出，以便组件不直接 fetch 大模型端点。
20. 作为开发者，我想所有测试夹具使用显式假 Key，以便密钥扫描能区分真实泄露与测试样本。
21. 作为开发者，我想提交前扫描 staged diff 中的疑似 Key 并阻断，以便任何 API Key 都不进入 git。
22. 作为开发者，我想 ADR 记录为什么用档案而不是多套预设、为什么 Key 不进备份，以便后来者不会重做决定。
23. 作为用户，我想设置面板里能看到哪份档案正在生效，以便切换后不会困惑。
24. 作为用户，我想连通性测试的进行中与结果状态可见，以便不以为按钮失效。
25. 作为用户，我想新增档案时基于当前档案复制一份默认值，以便少填字段。

## Implementation Decisions

- **新增 `apiProfiles` 深模块**（配置档案模块）。接口包含：读取全部档案、读取激活档案、新增 / 重命名 / 删除档案、切换激活档案、从旧扁平设置迁移、生成导出用脱敏档案、从导入档案恢复（Key 置空）、生成入队快照。模块接受可注入的 storage adapter；生产适配器包裹 `chrome.storage.local`，测试用内存适配器。
- **存储结构**：`ai_profiles` 保存具名档案数组，`active_profile_id` 指向当前档案。每份档案的字段沿用现有 `AISettings` 全集，不新增配置维度。旧 `ai_settings` 只作为迁移来源读取，不再写入。
- **模块边界保持**：读取当前 AI 设置的既有入口改为委托给配置档案模块，返回激活档案内容；所有 AI 调用点无需改动，仍从 AI 模块读取。
- **队列快照**：新任务入队时把激活档案的完整内容写入任务快照；队列引擎继续通过 `loadSettings` 端口读取设置，接线改为从任务快照读取。在途任务不感知识别档案切换。
- **连通性测试公共函数**：从 AI 模块导出 `testApiConnection`，接受一份档案（用于测试未完成编辑的档案），复用 `normalizeEndpoint` 与 `mapHttpError`，使用极小 `chat/completions` 请求（`max_tokens=1`），返回结构化结果：成功含耗时与模型名；失败含分类原因（配置缺失 / 鉴权 / 网络 / 响应）。组件通过该函数调用，不直接 fetch。
- **Key 隔离**：
  - 导出备份用脱敏档案（Key 置空），不再导出含 Key 的完整设置。
  - 导入备份时接受档案数组或旧扁平 settings；导入的档案 Key 一律置空，并提示用户重新填写。
  - 测试夹具只用显式假 Key（统一前缀 `sk-test-`），扫描规则据此设置豁免。
  - 增加提交前检查脚本：扫描 staged diff，命中疑似真实 Key 模式且不在显式豁免内即非零退出。仓库文档与 CI 都记录该检查；不依赖个人记忆。
- **接口预设**：继续只填接口地址与模型名，作用在正在编辑的档案上；不覆盖 Key、提示词与批次上限。
- **ADR-0007** 记录多档案 + Key 隔离决策，并明确它与 ADR-0002 的关系：落实 ADR-0002 第 4 条此前未实现的约束。
- **不涉及新域名**：连通性测试只能访问 `host_permissions` 已列域名；新增供应商仍需改清单并发版。

## Testing Decisions

- 好测试只测外部行为，不测实现细节；断言走公共接口，不绕过接口查存储内部。
- **Seam 1 — 配置档案模块**：用内存 storage adapter 测试档案 CRUD、激活切换、旧设置迁移、导出脱敏、导入 Key 置空、入队快照不随切换变化。这是档案逻辑的唯一测试缝。
- **Seam 2 — AI 连通性测试函数**：沿用现有 `vi.stubGlobal('fetch', ...)` 与 `vi.stubGlobal('chrome', ...)` 模式，断言极小请求体、`max_tokens=1`、成功返回耗时/模型名、各失败分类；不测组件内部状态。
- 既有 seam 不重复测试：三阶段提示词与解析已有快照与纯函数测试，队列引擎已有端口注入测试；本次不新增这些领域的测试。
- 提交前 Key 扫描用一次真实 staged diff 验证：放入假 Key 应通过，放入疑似真实 Key 应阻断（在临时仓库或临时 staged 状态验证，避免污染主提交）。
- 不新建组件测试底座；设置面板的交互由人工冒烟覆盖（沿用仓库现有的浏览器冒烟方式）。

## Out of Scope

- 新增 AI 供应商域名到 `host_permissions`（需要发版，另开工单）。
- 改三阶段分析逻辑、提示词内容或队列调度算法。
- 给档案增加云端同步或跨设备复制（本地优先，无后端）。
- 在设置面板之外增加快捷切换入口（如主界面下拉框）。
- 为连通性测试做流式响应或长文本生成；只允许极小请求。
- 自动轮换 / 负载均衡多个档案。
- 在导出备份里加密保存 Key（选择的是不保存）。

## Further Notes

- 本 spec 承接已接受的 ADR-0007；工单号确定后回填 ADR 的「相关工单」。
- 「接口预设」与「API 配置档案」是两个不同概念，词汇表已区分；写 UI 文案时不要混用。
- 用户硬约束「任何 API Key 都不得进入 git 提交」是验收条件，不是建议；实现与 code-review 都要检查。
