# ADR-0003：三阶段渐进式流水线 + 两遍标签聚类 + 整批单次打标

- **状态**：已接受
- **日期**：2026-11-24
- **相关工单**：`.scratch/foundation/issues/04-glossary-and-adr.md`

## 背景

一个收藏夹常有数百篇内容。用户真正的诉求不是"每篇都读完"，而是"先判断哪些值得留，再决定怎么归类"。若一开始就对全部文章读全文，成本与等待时间都不可接受；若逐篇分类，标签会随文章数发散（同一主题出现七八种说法），且请求数等于文章数。

## 决策

1. **三阶段递进，产物逐段落库**：粗读（`quick`）→ 词条分类（`categorize`）→ 精读（`deep`）。每个阶段有独立的完成标记（`aiProcessedAt` / `aiClassifiedAt` / `aiDeepReadAt`），可单独重跑，也可只跑其中一段。
2. **粗读截断 3000 字**，只回答"值不值得留"，不追求完整性；被截断的文章标记 `isTruncated`，提示用户可转精读。
3. **分类分两遍**：
   - **Pass 1 全局聚类**：把本批文章的主题收敛成有限标签池（默认上限 8，可自适应）。
   - **Pass 2 整批单次打标**：**一次请求**为整批文章返回标签与收藏夹归宿，标签只能取自标签池。
4. **精读才读全文**，并附带热评 Top 5，产出评论区洞察。
5. **阶段是建议而非强制**：分类可以在没有粗读产物时运行，但质量会下降；UI 不阻止，只在跳过规则上按阶段完成标记提示。

## 后果

- **成本随阶段递减**：粗读覆盖全部，分类按批请求，精读只用于筛后的少数文章。
- **跳过逻辑必须按阶段字段判断**，不能用 `tags` 之类可被手工修改的字段（见 ADR-0004）。
- **Pass 2 是单点失败放大器**：一次请求失败会整批标记 `failed`，需要"重试失败项"这条恢复路径；这是整批单次换来的代价。
- **标签池是分类质量的上限**：池子收敛得差，后面再怎么打标也不会好。因此 Pass 1 允许按 `chunkSize * 2` 周期重新收敛，兼顾稳定与漂移。
- 阶段字段存在文章行上，使"这篇到哪一步了"成为可查询状态，而不是只能从队列推断。

## 备选方案

| 方案 | 否决理由 |
| :--- | :--- |
| 一次性全文分析 | 单篇成本最高，且用户尚未判断是否值得留，浪费在前 |
| 逐篇分类 | 请求数 × N，标签跨文章发散，无法形成统一体系 |
| 先聚类全部再读 | 需要先拿到全文或摘要才能聚类，与"先粗筛"顺序矛盾 |
