# ADR-0007：多份 API 配置档案并存，Key 不进入可提交文件

- **状态**：已接受
- **日期**：2026-11-27
- **相关工单**：[#15](../../.scratch/api-profiles/issues/15-api-profiles-and-key-isolation.md)、[#16](../../.scratch/api-profiles/issues/16-connectivity-test.md)

## 背景

原来只有一份扁平 `ai_settings`（见 ADR-0002），预设按钮只改接口地址与模型名。用户需要在多个 AI 平台之间切换，且每家有不同的 Key、模型和提示词偏好；单一配置无法表达。同时 ADR-0002 第 4 条规定「Key 不写入导出文件」，但现有备份实现把整个 settings（含 apiKey）写进 JSON，属于未落实的约束。用户另提出硬约束：**任何 API Key 都不得进入 git 提交**。

## 决策

1. **配置以「API 配置档案」为单位**：每份档案包含接口地址、模型、Key、提示词与批次上限，命名并持久化；`active_profile_id` 指向对新任务生效的档案。
2. **旧配置迁移为默认档案**：首次启动把现有扁平 `ai_settings` 导入为一份档案，保留旧数据；`ai_settings` 不再作为写入目标。
3. **队列任务在入队时快照配置**：任务自带当时的完整档案副本；运行中切换激活档案不影响在途任务，只影响之后新入队的任务。
4. **连通性测试走同一个公共缝**：从 `ai.ts` 导出测试函数，复用 `normalizeEndpoint` 与 `mapHttpError`，组件不直接 fetch；测试用极小请求（`max_tokens=1`）并返回耗时、模型名或分类错误。
5. **Key 隔离是硬约束**：Key 只存 `chrome.storage.local`；备份导出把档案中的 Key 置空，导入后要求用户重新填写；测试与文档只用 `sk-test-` 假 Key；`npm run check` 与 pre-commit hook 都扫描 staged diff，命中疑似真实 Key 即非零退出。
6. **新增域名仍需改 `host_permissions` 并发版**（继承 ADR-0002 第 5 条）。

## 后果

- 切换平台是一次档案切换，不再是逐项改地址 / 模型 / Key。
- 备份文件不再包含 Key：恢复后必须重新填写，这是刻意的可逆代价。
- 在途任务不会因为用户切换档案而中途换 Key / 换模型，结果可复现。
- staged diff 扫描会误报形似 Key 的普通字符串，需要提供明确的豁免路径（显式标注的测试夹具），而不是关闭扫描。

## 备选方案

| 方案 | 否决理由 |
| :--- | :--- |
| 只做预设按钮，指向预置平台 | 无法保存每家的 Key 与提示词，切换仍要手填 |
| 把多份配置塞进单个扁平对象 | 浅合并会串味，迁移与备份都难以保持不变量 |
| 允许 Key 写入导出文件 | 违背 ADR-0002 第 4 条与用户的 git 泄露约束 |
