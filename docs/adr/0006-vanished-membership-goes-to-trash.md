# ADR-0006: 成员关系消失时移入回收站，而非标记失效

- 状态：已接受
- 日期：2026-11-24
- 相关：ADR-0004（进度真相源）、ADR-0005（产物归属）、ticket 12 / 13 / 14

## 背景

同步收藏夹内容时，本地按 `collectionId` 存有一组成员行。知乎端可能存在「收藏夹还在，但里面少了几篇」的情况——用户在知乎整理收藏夹、批量取消收藏。当前 `handleFetchArticles` 只调用 `safeUpsertArticles`，只增不改不删，导致本地持续累积远端已不存在的成员，「全部」视图显示过期内容。

差集（本地有、远端无）必须区分两种事件：

1. **内容失效**：作者删除 / 设为私密 / 被知乎屏蔽。现有 `formatRawContent` 已能识别这类"幽灵条目"，在抓取时就地标记 `isDeletedOrInvalid = true`，远端仍会返回一个占位条目。
2. **成员关系消失**：内容本身可能完好，只是从这个收藏夹里被移除。同一内容在别的收藏夹可能还有成员行（ticket 12 定性：一行 = 一条成员关系）。

## 决策

**远端 id 集合中消失的成员行，移入回收站（`inTrash = true` + `trashedAt`），不标 `isDeletedOrInvalid`，不物理删除。**

配套三条约束：

1. **完整性护栏**：只在抓取完整（主接口分页走到 `is_end=true`）时计算差集。备用接口 `/contents` 只取第一页、响应结构异常、分页信息缺失时，`complete=false`，跳过差集——否则会把未抓到的正常成员批量误判为已取消收藏。`fetchCollectionContentsDetailed` 返回 `{ items, complete }` 承载该标志；`fetchCollectionContents` 保持原签名，供不关心完整性的只读场景使用。
2. **成员级隔离**：差集只比较同一 `collectionId` 下的行，且已在回收站的行跳过（不覆盖用户手工移入时的 `trashedAt`）。同一内容在其他收藏夹的成员不受影响。
3. **不碰 AI 产物**：只写 `inTrash` / `trashedAt`，摘要、评级、标签、时间戳原样保留。回收站可一键恢复；真正的物理删除仍只允许走用户显式确认的"从知乎线上取消收藏"。

## 为什么不用 `isDeletedOrInvalid`

- 语义错位：它表示"内容在知乎侧不可访问"，是客观事实；差集只说明"这条成员关系没了"，内容可能好好的，还可能在别的夹里。标失效会污染「已失效」筛选视图。
- 不可逆：当前没有一键清除失效标记的路径，误判后只能手工改库；回收站可以恢复。
- 职责重叠：`formatRawContent` 已经在抓取阶段识别真正的内容失效，差集不必重复这个判断。

## 为什么不做自动物理删除

本地 AI 产物与用户标记是核心资产（ADR-0001）。物理删除不可逆，且只有用户显式确认才能调用 `removeArticleFromCollection`。差集是同步副作用，不该获得这种权限。

## 后果

- 用户取消收藏后，本地行进入回收站，可在回收站视图查看与恢复；「全部」视图不再显示过期成员。
- 因抓取不完整而跳过差集时，UI 提示「抓取未完整，本次跳过成员失效检查」，不静默。
- 新增纯函数 `findVanishedMemberIds`，差集逻辑可离线测试；仓储层用 `bulkUpdate` 批量置位。
