# ADR-0001：文章数据的唯一真相源是 IndexedDB（local-first，无自建后端）

- **状态**：已接受
- **日期**：2026-11-24
- **相关工单**：`.scratch/foundation/issues/04-glossary-and-adr.md`

## 背景

扩展要保存两类数据：从知乎抓取的收藏夹与文章，以及本地生成的 AI 产物（摘要、标签、评级、评论洞察）与用户标记（回收站、勾选）。数据敏感度高——收藏内容属于个人阅读史，AI 设置里还有 API Key。项目由单人维护，没有运维预算。

## 决策

1. **所有业务数据落 IndexedDB**（`ZhihuDigestDB`，Dexie），包括收藏夹、文章、AI 产物、回收站状态。localStorage 只存三类东西：AI 队列检查点、自动整理草稿、以及设置以外的瞬时 UI 偏好。
2. **不引入自建后端。** 没有账号体系、没有遥测、没有第三方中转。
3. **AI 设置（含 API Key）存 `chrome.storage.local`**，与业务数据分开，便于用户单独清除。
4. **数据出站口只有两个**：Markdown / Obsidian 导出（`exporter.ts`）与本地 JSON 备份（`backup.ts`）。二者都由用户显式触发。

## 后果

- **没有跨设备同步**，这是明确的产品边界，不是待补的缺陷。换机靠手动备份文件。
- 容量受浏览器配额约束；文章正文全量存储，长期使用需关注占用。
- 用户清除浏览器数据即丢失全部分析结果，因此备份是唯一保险，UI 需要保持可见入口。
- 表结构变更必须走 Dexie `version(n).stores(...)` 升级，不能就地改字段语义。
- 任何"把数据放服务端"的提案都与此 ADR 冲突，需先重开本决策。

## 备选方案

| 方案 | 否决理由 |
| :--- | :--- |
| 自建后端 + 账号 | 单人项目承担运维与合规成本；收藏内容上云放大隐私面 |
| 纯 localStorage | 容量与查询能力不足，无法支持按标签/收藏夹筛选 |
| 浏览器云同步（chrome.storage.sync） | 配额极小（约 100KB），且会把阅读数据交给账号同步 |
