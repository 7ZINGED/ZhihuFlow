## 💡 为什么需要「知流 · ZhihuFlow」？

知乎收藏夹往往是用户沉淀干货的宝库，但时间一长常常演变为“知识垃圾场”：
1. **「收藏从未停止，阅读从未开始」**：收藏了成百上千篇长文与问答，动辄数万字，完全没时间细读。
2. **「分类极度混乱，标签泛滥膨胀」**：早期分类随心所欲，跨领域内容混杂；自己打标容易千奇百怪、无法收敛，难以检索。
3. **「失效内容扎堆，逐篇操作繁琐」**：大量作者物理删帖或被封禁，知乎网页端缺少多选、批量分类转移和批量清理等实用工具。

**知流 · ZhihuFlow** 借鉴了开源项目 **[PathGao/MoonDigest](https://github.com/PathGao/MoonDigest)** 的设计哲学，重构了一套专为长文问答优化的 **三阶段渐进式流水线**、**Two-Pass 全局标签聚类** 与 **整批单次极速打标 (Batch One-Shot)** 系统，兼顾深度、效率与低 Token 成本。

## ✨ 核心特性一览

### 1. 🔄 三阶段渐进式 AI 流水线 (3-Stage Pipeline)
根据阅读深度分步推进，拒绝无脑全文调用，极大节省时间与费用：

- ⚡ **阶段一：快速粗读 (Quick Triage)**
  - 正文 3000 字智能截断快速初筛；
  - 生成 1~5 星质量评分与一句话判定建议；
  - 三态分拣：🟢 **值得留 (Keep)** / 🔴 **可清理 (Discard)** / 🟡 **待粗读初审 (Review)**。
- 🏷️ **阶段二：批量词条分类 (Batch Categorization & Taxonomy Clustering)**
  - **Pass 1 全局自适应聚类**：大模型根据当前子批次文章宏观提炼 5~7 个规范标签，引导全局收敛，彻底杜绝标签泛滥膨胀；
  - **Pass 2 整批单次极速打标 (Batch One-Shot)**：单次网络请求打包整批文章（默认 20 篇，可自由调节），AI 一次性输出整批标签与目标收藏夹归宿，**通信次数锐减 90%+，速度提升 10x+**；
  - 支持自定义每个条目最大标签数（默认 1~2 个）以及已有标签覆盖保护开关。
- 📖 **阶段三：全文精读 (Deep Read)**
  - 突破长度截断进行全文深度剖析；
  - 提炼核心摘要、3~5 条 **Key Takeaways 核心金句**；
  - 自动抓取热门神评，生成 **评论区高赞焦点与争议洞察 (Hot Comments & Insight)**。

---

### 2. 🛡️ 增量安全合并机制 (Safe Upsert)
- **刷新收藏夹数据不丢失**：拉取知乎线上最新变动（点赞数、评论数、正文更新）时，以内容 ID 智能对齐，**100% 完整保留本地已生成的 `tags`、`aiTriageRating`、`aiSummary`、`aiKeyTakeaways`、评论洞察及时间戳**；
- 杜绝再次同步知乎内容时本地分析成果被全盘抹除的问题。

---

### 3. 🎯 智能去重跳过与多维快捷状态筛选
- **智能跳过已处理项 (Smart Skip)**：
  - 触发批量粗读/精读/分类时，智能识别已处理条目，弹窗提示一键跳过已读内容，仅对未处理项推进排队，避免重复消耗 Token；
  - 若设置关闭“允许覆盖标签”，批量分类会自动跳过已有标签文章并给出友好提示。
- **分拣台顶部药丸筛选栏**：
  - `全部` / 🕒 **`待粗读`**（未评级文章）/ 🟢 **`值得留`** / 🔴 **`可清理`** / 🟡 **`不确定`** / 🏷️ **`未打标`**（无标签文章）/ ⚠️ **`已失效`**（原作者删除/平台封禁幽灵条目）；
  - 点击对应状态后点击「全选」，即可精准无遗漏地推进下一阶段批量处理。

---

### 4. 🗂️ 跨收藏夹智能自动重分类 (Auto-Organize)
- **多源收藏夹交叉分析**：支持多选勾选若干来源收藏夹（如“待读”、“临时”、“综合”），统一交由 AI 进行跨领域识别；
- **智能归类推荐与交互调整**：AI 给出目标收藏夹及推荐理由，支持在弹窗内直接人工下拉切换目标；
- **预演模式 (Dry Run)**：先查看完整整理方案与统计分布，确认满意后再一键通过知乎官方 API 真正执行转移或复制。

---

### 5. ⚡ 高可用异步队列与熔断保护 (AI Queue System)
- **悬浮进度控制栏**：实时显示当前批次、当前篇目、处理速度，支持随时**暂停、继续、清空中止**；
- **断点续传与持久化**：刷新页面或关闭窗口后队列状态自动恢复，不错过长任务进度；
- **连续异常熔断**：遇到网络断连或 API 配额耗尽时（连续失败 3 次），系统自动挂起队列保护，防止盲目重试；
- **错误智能折叠与单项重试**：过滤冗长网络堆栈，提供一目了然的友好中文错误，支持点击一键重试所有失败项。

---

### 6. 📝 本地优先、隐私安全与多端导出
- **Local-First 本地优先 (IndexedDB)**：基于 Dexie.js 将全部文章、全文、AI 分析产物缓存在浏览器本地，毫秒级即时检索与标签过滤，离线亦可浏览；
- **严格隐私安全**：无任何专属后端服务器，数据仅在用户浏览器与知乎 / 用户的 AI API 端点间流转；
- **多格式导出与知识库联动**：
  - **导出标准 Markdown**：包含 YAML Frontmatter 元数据、AI 提炼观点及正文备份；
  - **Obsidian 直写 (URI Protocol)**：点击图标直接将精读笔记追加至本地 Obsidian 知识库；
  - **富文本/Markdown 快速复制**：方便随时粘贴至 Notion、FlowUs、Logseq。

## 🚀 安装与上手指引

### 方式一：加载预编译扩展（最简单）

1. 在项目根目录运行 `npm run build` 生成构建产物（或直接从 Release 下载预编译包并解压出 `.output/chrome-mv3`）；
2. 打开 Chrome 或 Edge 浏览器，访问扩展管理页面：
   - Chrome: `chrome://extensions/`
   - Edge: `edge://extensions/`
3. 开启右上角的 **「开发者模式」 (Developer mode)**；
4. 点击左上角 **「加载已解压的扩展程序」 (Load unpacked)**；
5. 选择本项目下的 `.output/chrome-mv3` 文件夹；
6. 在知乎网页登录账号，点击扩展图标即可打开「知流 · ZhihuFlow」分拣台！

### 方式二：本地源码开发

```bash
# 1. 克隆代码仓库
git clone https://github.com/YOUR_USERNAME/ZhihuFlow.git
cd ZhihuFlow

# 2. 安装依赖
npm install

# 3. 启动开发模式 (基于 WXT 支持热重载与快速刷新)
npm run dev

# 4. 编译生产版本
npm run build
```

## ⚙️ AI 接口与自定义配置

点击分拣台右上角的 ⚙️ 齿轮图标，即可进行全维度个性化定制：

### 1. 模型提供商配置
系统遵循标准 OpenAI 兼容协议，支持市面主流大模型：

| 提供商 | API 地址 (Base URL) | 推荐模型名称 |
| :--- | :--- | :--- |
| **DeepSeek 官方** | `https://api.deepseek.com/v1` | `deepseek-chat` |
| **OpenAI** | `https://api.openai.com/v1` | `gpt-4o-mini` / `gpt-4o` |
| **月之暗面 (Kimi)** | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| **阿里通义千问** | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| **本地 Ollama** | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` (无需 API Key) |

### 2. 提示词与批量策略自由定制
- **自定义分拣标准**：自由修改快速粗读初筛 Prompt，明确哪些内容属于“留存”与“清理”；
- **自定义词条打标**：自由修改词条打标 Prompt，定义标签颗粒度风格；
- **批次篇数微调（无上下限限制）**：
  - 快速粗读单批上限（默认 30 篇，可任意填写）；
  - 词条分类单次打包篇数（默认 20 篇，可任意填写）；
  - 全文精读单批上限（默认 10 篇，可任意填写）；
- **全局标签池清理与重置**：一键抹除脏标签，配合全局标签自适应聚类重新规范打标。
